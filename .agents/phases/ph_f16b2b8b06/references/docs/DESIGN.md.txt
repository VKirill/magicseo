# Интерфейсы плагинов BB: стиль Pokecut и родные компоненты

Единый справочник для экранов всех собственных плагинов BB-сервиса. Экран
плагина собирается из двух слоёв, и оба обязательны:

1. **Структура** — родные компоненты BB (реестр `@bb`, компоненты SDK). Они дают
   поведение, доступность и совместимость с хостом; свои аналоги не пишутся.
2. **Внешний вид** — наш фирменный стиль **Pokecut**: серая подложка, белые
   карточки с волосяной рамкой и мягкой тенью, сегменты с приподнятым белым
   вариантом, розово-фиолетовый градиент на главном действии, мягкие
   тонированные статусы. Тот же язык, что у темы
   [Pokecut для BB](../plugins/bb-plugin-pokecut-theme/README.md), поэтому
   плагин выглядит частью приложения, а не отдельным виджетом.

| Что | Где канон |
| --- | --- |
| Значения цветов, теней и градиента (`--pk-*`) | `plugins/bb-plugin-pokecut-theme/src/theme/base.css` |
| Правила применения стиля в плагинах | этот файл |
| Готовые классы для копирования | [`docs/design/pokecut-plugin.css`](design/pokecut-plugin.css) |
| Эталонный экран в живом BB | Lane Pilot: `plugins/bb-plugin-lane-pilot/app.css` |
| Композиция конкретного экрана | `DESIGN.md` рядом с плагином (агентство, MCP и др.) |

Снимок состава компонентов: BB `desktop-v0.43.1`, Plugin SDK `0.4.87`, сверено
2026-09-14. Стиль Pokecut: тема 0.4.1, Lane Pilot `app.css`, сверено 2026-10-02.

## Часть 1. Стиль Pokecut

### Подключение

1. Скопируй `docs/design/pokecut-plugin.css` в `app.css` плагина после импортов
   Tailwind. Замени `SLUG` на id плагина, `xx-` — на короткий префикс плагина
   (`lp-` у Lane Pilot). Префикс обязателен: эти классы сборка не изолирует, и
   одинаковое имя у двух плагинов даст чужие стили на твоём экране.
2. Классы стоят в `@layer components`, поэтому утилита Tailwind на элементе
   перекрывает их — точечная правка не требует `!important`.
3. Классы навешиваются на компоненты `@bb`, а не заменяют их:
   `<Button className="xx-accent">`, `<Switch className="xx-switch">`,
   `<div className="xx-panel">…<Table/>…</div>`.

Токены плагина (`--xx-*`) читают `--pk-*` темы с запасным значением из палитры
BB. Поэтому с выключенной темой Pokecut экран остаётся опрятным, а со
включённой — совпадает с оболочкой. Шестнадцатеричные цвета в разметке и
классах не пишутся: значение берётся из токена, иначе тёмная тема и смена темы
его не перекрасят.

### Поверхности

| Класс | Что это | Когда |
| --- | --- | --- |
| `xx-panel` + `xx-panel-head` + `xx-panel-body` | Серая лунка (16px) с заголовком и белой карточкой внутри (12px) | Основной блок с названием: список, настройки, сводка |
| `xx-card` | Одна белая карточка (14px) | Самостоятельный результат без заголовка-лунки |
| `xx-strip` | Тихая полоса заголовка страницы (14px) | Один раз сверху: H1, метаданные, действия страницы |
| `xx-raised` | Белая поверхность с контуром и тенью | Вторичная кнопка, поле на сером фоне, чип |
| `xx-tile` | Квадратная плитка под иконку (9px) | Иконка или статусный знак рядом с названием |

Вложенность одна: лунка → белая карточка. Карточка в карточке в карточке не
используется — третий уровень делается разделителем или отступом, иначе экран
превращается в матрёшку рамок. Карточка нужна самостоятельному блоку, а не
каждой паре полей.

### Шкала радиусов

| Элемент | Радиус |
| --- | --- |
| Строки (навигация, список, меню), кнопки, поля, селекты | 8px |
| Сегмент внутри трека | 6px (трек 9px) |
| Внутренняя белая карточка, пузырь, блок кода | 12px |
| Одиночная карточка, полоса заголовка | 14px |
| Панель: серая лунка с заголовком и карточкой | 16px |
| Диалоги, панель содержимого приложения | 20px |
| Статусы, счётчики, «?» | полностью круглые |

Выбранный элемент не получает радиус больше соседей: выделение передаётся
поверхностью, а не формой.

### Действия и выбор

- **Главное действие** — `xx-accent` (градиент `--pk-accent-gradient`). Одно на
  экран или диалог: два градиента спорят за внимание.
- **Вторичное** — `xx-raised` (белое, контур, тень), обычно `Button
  variant="outline"`. **Третичное** — `variant="ghost"`. **Опасное** —
  `variant="destructive"` и подтверждение через `alert-dialog`.
- **Сегменты** (`xx-seg` / `xx-seg-item`) — переключение 2–5 срезов одного
  набора. Подходят для `toggle-group` и `tabs`: активный вариант читается по
  `data-state="active"` или `aria-pressed="true"`.
- **Навигация** (`xx-nav-item`) — строки тихие, выбранная становится белой
  приподнятой плашкой (`aria-current="page"` или `aria-selected="true"`).
- **Переключатель** — `@bb/switch` с `xx-switch`: включённый — градиент.

### Статусы и цвет

Статус — мягкая тонированная пилюля `xx-pill` с вариантом:

| Вариант | Смысл |
| --- | --- |
| `xx-pill-success` | готово, работает, совпадает |
| `xx-pill-info` | идёт, в очереди, сведения |
| `xx-pill-warning` | частично, расхождение, требует внимания |
| `xx-pill-danger` | ошибка, нет, остановлено |
| `xx-pill-neutral` | нейтральный признак на белом |
| `xx-pill-muted` | тихая метка, неактивно |

Цвета статусов — только токены BB (`--success`, `--warning`,
`--destructive`, `--timeline-accent` и их `-text`), их перекрашивает тема.
Tailwind-палитра (`emerald-500`, `amber-500` и т. п.) в новых экранах не
используется: она не меняется вместе с темой и выпадает из стиля. В разметке те же токены доступны утилитами Tailwind сборки плагина:
`bg-success`, `bg-success/15`, `text-diff-added`, `bg-warning`,
`text-warning-text`, `bg-destructive`, `text-destructive-text`,
`text-timeline-accent`. Цвет никогда
не единственный носитель смысла: в пилюле слово, у точки — `aria-label` и
легенда.

Знак помощи «?» — `xx-help`: круг 14px, поднятый к верху строки заголовка,
сразу после последнего слова; пояснение в `tooltip` или `popover`.

### Типографика и ритм

| Уровень | Стиль |
| --- | --- |
| Заголовок страницы (один H1, в `xx-strip`) | `text-xl font-medium` |
| Заголовок блока (H2, в `xx-panel-head`) | `text-sm font-medium` |
| Основной текст и строки | `text-sm` |
| Метаданные, пути, подписи | `text-xs text-muted-foreground` |
| Числа, идентификаторы, хэши | `font-mono tabular-nums` |

Шрифт — Inter оболочки BB; свои шрифты не подключаются. Промежутки: 4–8px
внутри группы, 12px между карточками одной колонки, 20–24px между секциями.
Строка коллекции на широкой панели — 48–56px. Рабочая область ограничена по
ширине (`max-w-5xl`, по центру): растянутая на весь монитор таблица не
читается.

### Коллекции и пустые состояния

Перечень однотипных сущностей — `@bb/table` внутри `xx-panel-body` (или
`xx-card`): шапка колонок, разделители строк `divide-border/60`, действия справа
проявляются при наведении и фокусе, но остаются в потоке. Пустое состояние —
внутри той же карточки: одна строка «что здесь будет», одна строка «как
появится» и одно действие `xx-accent`, если его можно сделать отсюда.
Загрузка — `@bb/skeleton` той же формы, что и данные.

## Часть 2. Родные компоненты BB

### Три источника готового UI

1. **Реестр `@bb`** — вендоренные shadcn-компоненты, сгенерированные из
   исходников самого BB. Копируются в плагин и принадлежат ему.
2. **Компоненты SDK** (`@get-bb/plugin-sdk/app`) — продуктовые возможности BB:
   чат, markdown, просмотр кода и диффов, пикеры провайдера и модели. Их не
   копируют и не переписывают.
3. **Шимы рантайма** — пакеты, которые BB подменяет своими экземплярами
   (react, портальные radix, sonner, vaul). Импортируются свободно, но в
   `dependencies` не попадают.

Отдельного «host component kit» больше нет: `EmptyState`, `PageBody`,
`Spinner` из старых версий удалены, их пишут сами (это несколько строк).

### 1. Реестр `@bb`

Установка стоковым инструментом shadcn, имена с префиксом реестра:

```bash
npx shadcn@latest add @bb/table @bb/badge @bb/tooltip
npm install           # каждый компонент тянет свои зависимости
```

Файлы ложатся в `components/ui/`, импорт через алиас `@/`:
`import { Table } from "@/components/ui/table"`. Копии принадлежат плагину и
не меняются сами; повторный `shadcn add` — способ обновить их вручную.

`bb plugin new` сразу кладёт `button`, `card`, `input`, `checkbox`, `dialog`,
`icon`, `responsive-overlay`, `drawer` и вспомогательные файлы.

#### Состав реестра (44 позиции)

**Ввод и формы**

| Компонент | Для чего |
| --- | --- |
| `button` | Действия. Варианты `default / secondary / outline / ghost / destructive / link`, размеры `default / sm / lg / icon`. Пропса `title` нет — подпись через `aria-label`. |
| `input`, `textarea`, `label` | Поля ввода и подписи к ним. |
| `checkbox`, `switch`, `radio-group` | Флажок, переключатель состояния, выбор одного из вариантов. `switch` — собственная реализация BB, без radix. |
| `select` | Выпадающий выбор одного значения. Портальный — шимится хостом. |
| `slider` | Числовой диапазон. |
| `input-otp` | Ввод кода из отдельных ячеек. |
| `form` | Обвязка react-hook-form: `FormField`, `FormItem`, `FormMessage`. Нужна только для сложных форм с валидацией. |
| `calendar`, `toggle`, `toggle-group` | Выбор даты, переключаемая кнопка, группа переключателей. |
| `command` | Палитра команд и поиск по списку. |

**Данные и вывод**

| Компонент | Для чего |
| --- | --- |
| `table` | Перечень однотипных сущностей: `Table, TableHeader, TableBody, TableRow, TableHead, TableCell`. Основной способ показать коллекцию. |
| `badge` | Короткая метка состояния. Варианты `default / secondary / destructive / outline`. |
| `card` | Самостоятельный блок: результат, запрос, сводка. Не обрамление каждой пары полей. |
| `avatar` | Портрет участника или иконка сущности. |
| `progress`, `skeleton` | Ход выполнения и заглушка на время загрузки. |
| `chart` | Графики (recharts). Тянет заметные зависимости — ставить по необходимости. |
| `separator` | Тонкий разделитель секций. |
| `aspect-ratio` | Фиксированные пропорции для медиа. |

**Оверлеи и раскрытие**

| Компонент | Для чего |
| --- | --- |
| `dialog` | Модальное окно. На узком экране BB сам показывает его снизу как drawer — API тот же. |
| `alert-dialog` | Подтверждение опасного действия. |
| `drawer`, `sheet` | Панель снизу и панель сбоку. |
| `popover`, `hover-card`, `tooltip` | Всплывающий блок по клику, по наведению, короткая подсказка. |
| `dropdown-menu`, `context-menu`, `menubar` | Меню действий: по кнопке, по правой кнопке, строка меню. |
| `collapsible`, `accordion` | Раскрытие вторичных подробностей. |
| `responsive-overlay` | Обёртка BB, выбирающая диалог или drawer по ширине. |

**Навигация и каркас**

| Компонент | Для чего |
| --- | --- |
| `tabs` | Независимые рабочие контексты. Для срезов одного набора данных — фильтры, а не вкладки. |
| `breadcrumb`, `pagination` | Путь назад и постраничная навигация. |
| `navigation-menu` | Сложное меню разделов. |
| `scroll-area` | Прокручиваемая область с оформленным скроллбаром. |
| `resizable` | Разделяемые панели. |
| `carousel` | Горизонтальная лента. |
| `alert` | Заметное сообщение в потоке страницы. |

**Оформление BB**

| Компонент | Для чего |
| --- | --- |
| `icon` | Единый компонент иконок BB: `<Icon name="Check" />`. Имена — из `components/ui/icon.tsx`. |
| `icon-extended` | Расширенный набор имён (`Laptop`, `Cloud`, `Globe`, `Plug02`, `ElectricPlugs`, …), список в `icon-registry.ts`. |
| `motion` | Общие константы переходов, например `CONTROL_HOVER_TRANSITION`. |

В реестре нет `sidebar`, `sonner`, `toast`, `date-picker`: боковую панель даёт
сам BB, уведомления приходят через шим `sonner`, выбор даты собирается из
`calendar` и `popover`.

### 2. Компоненты SDK

Импорт из `@get-bb/plugin-sdk/app`. Не бандлятся, живут в хосте.

| Компонент | Назначение и главные пропсы |
| --- | --- |
| `ThreadChat` | Полноценный чат треда внутри плагина: `{ threadId, variant: "full" \| "compact" \| "timeline", layout, permissionPolicy, leadingContent, messageActions }`. Не проксировать данные треда своим RPC и не собирать свой композер. |
| `experimental_NewThreadComposer` | Полная форма создания треда: промпт, вложения, выбор провайдера/модели, окружение, права. Не писать textarea + кнопку «Создать». |
| `Markdown` | Разметка сообщений с типографикой чата: `{ content, className }`. |
| `UrlLink` | Настоящая ссылка, уважающая настройку «в приложении / во внешнем браузере». Для кнопок — `useBbNavigate().openUrl(url)`. |
| `experimental_FileLink` | Ссылка на файл: `{ kind: "workspace" \| "host" \| "thread-storage", … }`, открывает штатный просмотр BB с контекстным меню. |
| `experimental_SourceCode` | Просмотр исходника с подсветкой и темой BB: `{ content, path, overflow, highlightedLines }`. |
| `experimental_Diff` | Просмотр диффа одного файла: `{ patch, path, view: "unified" \| "split" }`. Не импортировать `@pierre/diffs` напрямую. |
| `experimental_ProviderModelPicker` | Выбор провайдера, модели, уровня рассуждений: `{ value, onChange, routing }`. Не собирать каталог моделей самому. |
| `experimental_PermissionModePicker` | Выбор режима разрешений с учётом потолка машины. |
| `experimental_BranchPicker` | Выбор ветки проекта на машине. |
| `experimental_ProviderIcon` | Официальная эмблема провайдера (Claude Code, Codex, Cursor, Antigravity…): `{ providerKind: "agent", provider: { id, logoUrl?, icon? }, fallback?, className }`. Запись берут из `experimental_useProviders()` — те же данные, что читают штатные пикеры BB. Не хранить логотипы у себя. |

Хуки того же модуля: `useRpc`, `useRealtime`, `useRealtimeConnectionState`,
`useSettings`, `useBbContext`, `useBbNavigate`, `useComposer`,
`useComposerView`, `experimental_useProviders` (каталог провайдеров с
`logoUrl`), `experimental_useBranches`, `experimental_useCheckoutState`,
`experimental_useAppPanel`, `experimental_useCodeTheme`.

Уведомления: `import { toast } from "sonner"` — шим на Toaster хоста. Свой
`<Toaster>` не монтировать.

### 3. Зависимости: что куда

| Пакет | Где объявлять | Почему |
| --- | --- | --- |
| `react`, `react-dom` | `devDependencies` | Шим хоста; второй экземпляр сломает контекст. |
| Портальные radix: `react-dialog`, `-alert-dialog`, `-popover`, `-select`, `-dropdown-menu`, `-context-menu`, `-menubar`, `-hover-card`, `-tooltip`, `-navigation-menu` | `devDependencies` | Шим хоста: общий слой фокуса и блокировки прокрутки. |
| `sonner`, `vaul`, `@pierre/diffs` | `devDependencies` | Шим хоста. |
| `clsx`, `tailwind-merge`, `class-variance-authority` | `devDependencies` | Не бандлятся ради размера. |
| Непортальные radix (`react-checkbox`, `react-separator`, `react-slot`, …), `@hugeicons/*`, recharts и прочее | `dependencies` | Бандлятся из вашего `node_modules`. |
| `zod` | `dependencies` | Не шимится, нужен и на сервере. |

`bb plugin types` пришпиливает версии шимов к текущему BB,
`bb plugin types --check` показывает расхождение. Пакет из шим-списка в
`dependencies` ломает установку из git.

## Часть 3. Проверка экрана перед сдачей

Проверяется в живом BB после `bb plugin build .` и `bb plugin reload <id>`, а
не по коду:

- [ ] Пустое состояние, данные, длинное название, ошибка, недоступная машина.
- [ ] Узкая панель (порог содержимого 880px) и телефон (< 768px).
- [ ] Тема **Pokecut** светлая и тёмная — экран совпадает с оболочкой.
- [ ] Тема **Default** — запасные токены дают опрятный вид, без «голых» белых
      карточек на белом и без потерянных рамок.
- [ ] Одно главное действие с градиентом; радиусы по шкале; статусы — пилюли.
- [ ] В CSS и разметке нет шестнадцатеричных цветов и палитры Tailwind для
      статусов; все классы с префиксом плагина.
- [ ] Клавиатура: фокус виден, выбранный сегмент и строка навигации отмечены
      `aria-*`, а не только цветом.
- [ ] Английский и русский интерфейс: длинные русские подписи не ломают
      сегменты и кнопки.

## Продуктовые DESIGN.md плагинов

Рядом с плагином живёт его собственный `DESIGN.md`: композиция экранов,
состав колонок, сценарии. Общую базу из этого файла он не повторяет. Если
продуктовый документ задаёт другой цвет или форму (например, старую палитру
`emerald-500 / amber-500`), действует этот файл; продуктовый документ
приводится к стилю Pokecut при переработке интерфейса плагина, а не массовой
правкой.
